# 文昌帝君陰騭文｜互動電子書

《文昌帝君陰騭文》（道教勸善文，以文昌帝君的名義流傳，通行本 636 字）的網頁電子書：原文、白話、註解、注音、朗讀，加上幾種取自原文的互動。蔬米 OMILKYWAY「經典互動」系列之一，和《太上感應篇》《十善業道經》電子書、弟子規小遊戲、三款遊記遊戲同一個家族；程式是從《太上感應篇》那一本（`taishang-ganying-pian`）改寫來的。

正式網址：<https://edu.omilkyway.org/wenchang-yinzhi-wen/>

## 這本書有什麼

- **十一段、11 頁**：帝君自述、四個典故、心地福田、人倫敬信、濟急救危、公平公益、愛惜物命、十勿、修身處世、修路造橋、結語。《陰騭文》沒有傳統的分章，這十一段是本書依內容分的。原文一字不漏，每段有白話，難詞可以點開看註解，每頁可以朗讀。
- **60 顆種子**：四個典故一句一顆（金色的芽），善行一句一顆（綠芽），〈十勿〉一句一顆（青藍的芽）。點了才發芽、才顯示白話。
- **四個典故的故事卡**：第 2 頁的于公治獄、竇氏濟人、宋郊救蟻、叔敖埋蛇，點開那一句就看到完整的故事、插圖和出處。
- **生活情境題**：每頁一題，三個選項，選完給回饋，不計分。
- **古今對照**：原文裡的一句善行 ↔ 今天做得到的一件事（點夜燈以照人行 ↔ 通報壞掉的路燈），八組配對。接在第 10 頁後面。
- **我的福田**：取「欲廣福田，須憑心地」。一幅畫被十二塊還沒開的田蓋住，讀完一段就開一塊；第十二塊是「古今對照」。有種子的段要全部種下；沒有種子的段，讀過就算。
- **時時方便**：取「行時時之方便，作種種之陰功」。每天三項自我檢核（利人、利物、陰功），並累計做了幾件。
- **點圖放大**：封面、各頁插圖和故事卡的插圖點一下就全螢幕看完整的圖，點任意處、✕、Esc 或手機返回鍵關閉。「我的福田」要十二塊田都開了之後才能放大。
- **注音**：每頁「經文」標題列有一顆「注音：關／開」，和「朗讀」「白話」放在一起；預設關。打開後原文每個字的右邊顯示直式注音（課本那種排法；白話、註解、情境題不加），換頁、重開都記得。

進度只存在讀者自己的瀏覽器裡（`localStorage`，鍵 `yinzhiBook.v1`、`yinzhiDaily.v1`），沒有帳號。「顯示注音」的開關另外存在 `yinzhiPrefs.v1`，「清除閱讀進度」不會動到它。

**程式裡的名字：** 種子在程式裡沿用《太上感應篇》那本的「燈」——資料的 `role` 是 `lamps`，進度是 `lightLamp`／`isLit`／`litCount`，CSS 類別是 `.lamp`，設定是 `LAMP_COUNTS`／`TOTAL_LAMPS`。畫面上的字一律是「種子」。這樣兩本書的程式可以互相對照、修正可以互相搬。

**Google Analytics：** 評估 ID 寫在 `js/config.js` 的 `GA_MEASUREMENT_ID`，Google 代碼在 `index.html` 的 `<head>`，兩邊要一起改，`tests/html.test.js` 會檢查一致；留空字串就是沒裝，「關於本書」有 ID 才會多一句說明。GA 資源開在帳戶 OMILKYWAY.ORG 底下（這個系列各作品的資源都放在這個帳戶）。翻頁時 `js/app.js` 會自己送 `page_view`（標題是段名，網址用路由當路徑，例如 `…/wenchang-yinzhi-wen/ch/4`），GA 的「網頁和畫面」報表才看得出各段的閱讀量。

## 執行

```bash
npm install
npm run dev        # http://localhost:8010（不要直接雙擊 index.html，瀏覽器不讓 file:// 讀 JSON）
npx vitest run     # 全部測試
```

## 部署

整個資料夾就是純靜態網站，沒有建置步驟。GitHub Pages 設定為 `main` 分支根目錄，push 之後自動發布。自訂網域 `edu.omilkyway.org` 設在 `gustarsmile.github.io` 那個 repo，這裡不必設定。

換網址時要改兩處：`js/config.js` 的 `BOOK_URL`，以及 `index.html` 的 `og:url`、`og:image`（`tests/html.test.js` 會檢查兩邊一致）。

## 嵌入其他網頁

```html
<iframe
  src="https://edu.omilkyway.org/wenchang-yinzhi-wen/"
  title="文昌帝君陰騭文互動電子書"
  style="width: 100%; max-width: 560px; height: 820px; border: 0; border-radius: 8px; display: block; margin: 0 auto;"
  loading="lazy">
</iframe>
```

iframe 裡的進度和直接開網址的進度是分開的兩份（瀏覽器把它當成第三方儲存空間），而且 iPhone 的 Safari 關掉之後，嵌入頁面裡存的進度就沒了。所以旁邊最好再放一個「全螢幕開啟」的連結；書的封面在被嵌入時也會自己顯示這個提醒。被嵌入時翻頁用 `location.replace`，不留瀏覽歷程。

## 內容慣例（測試會守門）

- **原文不能動。** 所有 `raw` 依序串起來、去掉空白之後，必須和 `tests/fixtures/yinzhi-wen.txt` 逐字相同，標點也算（`tests/fidelity.test.js` 會指出第幾個字不同）。去掉標點後是 636 字，和 `tests/fixtures/yinzhi-wen-wikisource-bare.txt`（維基文庫通行本）逐字相同。
- **白話、註解、情境題、故事都是自己寫的**，不轉載別人的譯本。句子的意思依據清代朱珪的《陰隲文註》（公有領域，維基文庫有全文），並參考周安士的《文昌帝君陰騭文廣義節錄》。通行本比這兩家註本多出來的七處（見下面「原文的底本」）沒有古註可依，白話照字面的意思寫。
- 白話寫這句話通行的、直接的意思，用詞取委婉的一邊；註解特有的推論、區分、較重的說法寫在 `note`，並標明是註解說的。
- 原文是在「描述一種行為」，白話就照樣描述，不加評論。講神明與報應的地方照原文平實翻譯，不加油添醋、不引註解裡的報應故事、不寫嚇人的細節。不貶其他信仰，不寫療效或功效。
- 帶著時代背景的句子（忠於君主、奴僕、放生、敬惜字紙、不殺耕牛等），白話照翻，另外用 `note` 一句話交代背景；語氣平實，不批判古人、不替古人辯護，用詞要適合親子共讀。
- 原文的「常」是「總是、一再」，白話不要寫成「常常」。
- 區塊的 `terms` 引用 `glossary.json` 的鍵，那個詞必須真的出現在該區塊的 `raw` 裡；沒有被引用的詞條不能留。同一個字在不同地方意思不同時，開不同的鍵（`格-感通`、`格-糾正`、`濟-幫助`、`濟-渡`）。註解裡的注音，沒有十足把握的不要寫。
- 清單超過 12 列時要分組，同一組的每一列都寫相同的 `group`。
- `match.json` 每一組的 `raw` 必須是原文裡的句子；`now` 是本書寫的現代例子。
- 四個典故的故事要對過出處再寫：于公見《漢書・于定國傳》；竇禹鈞、宋郊、孫叔敖都依朱珪的註寫，前兩位並對照《宋史》（卷 263 竇儀傳只引了馮道詩的後兩句；卷 284 宋庠傳附宋祁）。孫叔敖的事另見劉向《新序・雜事》《列女傳・孫叔敖母》和賈誼《新書》，各書細節不同（《新序》是「歸而泣」，沒有「憂而不食」；「必興於楚」出自《列女傳》），所以出處標「依朱珪的註」，不要只標《新序》。
- 書名頁和導讀寫「相傳文昌帝君所說」「相傳是文昌帝君的訓示」，不寫「託名」（對信眾比較委婉）；成書與作者的討論放在「關於本書」。
- 2026-11-25 請獨立審稿人逐句對過朱珪、周安士兩家註和《漢書》《宋史》：白話沒有譯錯的句子；故事卡、出處、note 的歸屬和幾處轉述共改了二十多處（錯誤 2、偏差 9、建議 15，全部採納）。引用註解時，只有註解裡真的有的話才掛在「朱珪的註說」「周安士的註說」底下；自己的推論另起一句。

## 原文的底本

- 底本是通行本：維基文庫《文昌帝君陰騭文》，共 636 字。沒有改動任何字（恆、翦、貲、讎、錫、衾都照底本）。
- 新式標點和分段是本書自己加的。全篇不加引號。
- 做書時對校過五個本子（2026-11-25，用程式逐字比對）：
  - **維基文庫通行本**（636 字）：本書的底本。
  - **淨空法師專集網流通本**（620 字，<https://www.amtb.tw/pdf/wcdj.pdf>）：少「和睦夫婦，教訓子孫，毋慢師長，毋侮聖言」十六字；「捐貲」作「捐資」。其餘相同。
  - **時時抄經 App 本**（636 字）：和通行本差八個字——賜（錫）、聖賢（聖言）、名節（名利）、和諧（諧和）、恒（恆）、衿（衾），另有「賬濟」「眉捷」兩處應是錯字（賑濟、眉睫）。
  - **朱珪《陰隲文註》所註的本子**（約 545 字）和**周安士《陰騭文廣義節錄》所註的本子**（約 544 字）：比通行本少七處、共 92 字——「存平等心，擴寬大量」「和睦夫婦，教訓子孫，毋慢師長，毋侮聖言」「談道義而化奸頑，講經史而曉愚昧」「舉善薦賢，饒人責己」「造漏澤之仁園，興啟蒙之義塾」「依本分而致謙恭，守規矩而遵法度。諧和宗族，解釋冤怨」「恆記有益之語，罔談非禮之言」；「點夜燈以照人行，造河船以濟人渡」排在「禁火莫燒山林」的後面。朱珪本另作「網禽獸」「捐資」，周安士本另作「斗稱」「奴婢」「私仇」（周安士本的內文標題也作「網禽獸」，只有卷首的全文作「禽鳥」；另有「救急如濟涸轍之魚」等小異文，沒有全部列出）。
- 這些差異寫在書裡的「關於本書」；第 4 頁那十六個字另有一句說明。

## 注音

`js/data/zhuyin.json` 是全文 405 個不同的字的讀音，分三部分。`chars` 和 `poly` 分開放，是為了一眼看得出哪些地方是人工判斷：

- `chars`：單音字（辭典只列一個讀音），283 個，直接用辭典的讀音。
- `poly`：破音字（辭典列出兩個以上讀音），122 個。這裡寫的是**辭典列的第一個讀音**（《簡編本》的 (一)；《簡編本》沒收的字用《重編》的第一個），不一定是本文用到的讀音。
- `phrases`：本文裡**不讀第一個讀音的每一處**，也就是全部的人工判斷，共 11 處。鍵是原文裡連續的幾個字（要在同一段或同一列之內，不含標點），讀音用空白分開、一字一音。標音時詞句優先於單字，長的詞句優先於短的。

十處人工判斷（2026-11-25）：救人之難（難ㄋㄢˋ）、中狀元（中ㄓㄨㄥˋ）、宰相（相ㄒㄧㄤˋ）、為國救民（為ㄨㄟˋ）、大量（量ㄌㄧㄤˋ）、師長（長ㄓㄤˇ）、朝斗（朝ㄔㄠˊ）、暴露（ㄆㄨˋ ㄌㄨˋ，《簡編本》《重編》的詞條都是這個讀音）、本分（分ㄈㄣˋ）、德行（行ㄒㄧㄥˋ）。書的主人 2026-11-26 逐條確認，另外定了第十一處：上格蒼**穹**讀ㄑㄩㄥˊ（《重編》列為又音；《簡編本》只有ㄑㄩㄥ）。

另外幾處照第一個讀音、但值得再看一眼的：惡人則**遠**避之（ㄩㄢˇ，「遠遠地避開」；不是《太上感應篇》「眾邪遠之」當動詞的ㄩㄢˋ）、除**當**途之瓦石（ㄉㄤ，和「當道」的當一樣；維基文庫的夾註說通「擋」）、天必**錫**汝以福（ㄒㄧˊ，通「賜」但照本字讀）、士**大**夫（ㄉㄚˋ，不是醫生的ㄉㄞˋ ㄈㄨ）。

讀音的依據與慣例（和《太上感應篇》那本相同）：

- 以臺灣教育部的標準為準，不用大陸的普通話讀音，也不拿拼音工具轉換。查兩部辭典：《國語辭典簡編本》（依《國語一字多音審訂表》，現行教學用的標準讀音）和《重編國語辭典修訂本》（古義、讀音／語音／又音都收）。
- 《簡編本》只列一個讀音的字就用那個讀音。破音字依文意判斷，參考兩部辭典的釋義和例詞。
- 一聲不標調；二三四聲的調號寫在後面；輕聲的「˙」寫在前面。全篇是文言，不標輕聲（「兄弟」讀ㄒㄩㄥ ㄉㄧˋ、「規矩」讀ㄍㄨㄟ ㄐㄩˇ）。
- 「一」「不」照課本標變調（不睦ㄅㄨˊ ㄇㄨˋ）：資料和 `annotate()` 仍是本調，顯示時才由 `applySandhi()` 換掉，辭典查證用的也是本調。**「一十七世」的「一」讀本調**（ㄧ ㄕˊ）：這是數字裡十位上的一，和「一百」「一千」不同，`applySandhi()` 對「一十」有例外。
- 註解（`glossary.json`）裡寫了注音的字，同一處的注音必須一樣（`tests/zhuyin.test.js` 會比對；`node content-src/zhuyin-spot.mjs` 也會查）。
- 和現成注音本的比對（2026-11-25）：只找到一份流通的結緣本（高雄一間廟的結緣品，網友轉錄在痞客邦 <https://june213150.pixnet.net/blog/posts/5060151879>；544 字的短本，只替生難字和破音字標音）。它標了音、本書也有的 25 個字裡，22 個相同（含救人之**難**ㄋㄢˋ、**中**狀元ㄓㄨㄥˋ、**朝**斗ㄔㄠˊ、**種**種ㄓㄨㄥˇ、代天**行**化ㄒㄧㄥˊ 這幾處破音字）；3 個不同：蒼**穹**（結緣本ㄑㄩㄥˊ／本書ㄑㄩㄥ）、**矜**孤（ㄍㄨㄢ／ㄐㄧㄣ）、**衾**影（ㄑㄧㄣˊ／ㄑㄧㄣ）。這三處原本依教育部辭典，那篇轉錄底下的讀者留言也指出同樣的三處。2026-11-26 書的主人定：穹改讀ㄑㄩㄥˊ（《重編》的又音），衾維持ㄑㄧㄣ；矜暫時維持ㄐㄧㄣ（辭典的ㄍㄨㄢ同「鰥」，指老而無妻的人；這裡和「恤寡」對稱，是「憐惜」的意思），待再確認。
- 還沒有和「全文逐字注音」的讀誦本比對過。日後有可靠的注音本，照《太上感應篇》那次的做法：差異列給書的主人逐條決定。

查證用 `scripts/zhuyin-check.mjs`。它把全文每個不同的字逐字到兩部辭典查出所有讀音，存成快取（`content-src/zhuyin-dict/`，不進 repo），再檢查 `zhuyin.json`：

```bash
node scripts/zhuyin-check.mjs fetch    # 只查還沒查過的字（一次一個字、慢慢查）
node scripts/zhuyin-check.mjs init     # 從辭典快取起一份 zhuyin.json 的底稿（新書開工時用一次；phrases 會留著）
node scripts/zhuyin-check.mjs          # 檢查：每個字都標到音、選的讀音都在辭典列的讀音裡、chars／poly 沒放錯邊
node scripts/zhuyin-check.mjs --list   # 另外印出破音字清單：每一處的句子、選的讀音、兩部辭典列的讀音和釋義
node content-src/poly-list.mjs         # 精簡的破音字清單（一字一列，不印釋義；content-src 不進 repo）
node content-src/zhuyin-spot.mjs --all # 把全文連同顯示時的注音印出來，從頭唸一遍
```

標了「請人工確認」的幾類不算錯，但改動後要再看一眼。改了原文或 `zhuyin.json` 之後，先跑 `fetch` 再跑檢查。

畫面上，注音只在「注音：開」時才畫：`js/ui/gloss.js` 把原文的每個漢字換成 `<ruby>字<rt>注音</rt></ruby>`，標點不動，難詞的 `<span>` 還是原來那一個；關掉就換回純文字。`zhuyin.json` 讀不到時書照樣能讀，只是沒有這顆開關。排法是臺灣課本的**直式注音**（注音排在字的右邊，聲母、介音、韻母由上往下疊；調號在最後一個符號的右上方）。排版的細節和注意事項，見《太上感應篇》那本 README 的「注音」一節，兩本的程式相同；改了注音的 CSS，要在真的瀏覽器、390px 寬逐頁看過。

## 插圖

17 張（封面＋11 頁各一張＋「我的福田」的整張大圖＋四個典故各一張），用 gpt-image-2 生成。提示詞在 `scripts/art-prompts.mjs`，每張都以同一段風格前綴開頭（台灣廟宇彩繪、Q 版人物、多色且冷暖均衡、主角畫得大放前景、遠景小人最多兩三個、畫中不得有字）；反覆出現的文昌帝君和兩個孩子寫成固定的描述，各張才會長得一樣。兩個孩子（桃紅小女孩、寶藍小男孩）和《太上感應篇》那本是同一對。

```bash
node scripts/gen-art.mjs                 # 補齊 art-src/ 裡還沒有的圖
node scripts/gen-art.mjs c05-rescue      # 只重畫指定的圖
node scripts/contact-sheet.mjs           # 拼成對照表過目（art-src/_preview/）
npm run opt-art                          # art-src/*.png → assets/art/*.webp，並由封面產生 assets/og.png
```

`art-src/` 是原圖，不進 repo。新增一張圖要同時改三處：`scripts/art-manifest.mjs`、`scripts/art-prompts.mjs`、`chapters.json` 的 `art`（故事卡是 `story.art`）；換了圖要記得改 `chapters.json` 的 `alt`（封面和「我的福田」的 alt 在 `js/config.js`）。
